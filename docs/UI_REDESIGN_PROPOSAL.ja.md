# StagePane UI再設計企画

作成日: 2026年10月13日。対象: macOS版StagePane。状態: 8ラウンドのレビューを完了した実装前の設計提案。

2026年10月14日追記: 推奨案をネイティブUIへ実装し、設定の分類をさらに簡素化した。現在の設定は「一般」「このアプリについて」の2項目。プライバシーはAboutの要約と開閉式の詳細へ統合し、画面共有の説明は独立した案内ウインドウへ移した。以下の設計意図は維持し、実装後の検証は [レビュー記録](UI_REDESIGN_REVIEW_LOG.ja.md) に分けて記載する。

同日追加: レイヤーのドラッグ並べ替えとmacOSの外観への追従を実装した後、常設説明と重複操作を再整理した。操作を示すハンドル・具体的なラベル・状態表示を優先し、既にUIが表す手順の説明はツールチップとアクセシビリティのヒントへ移す。以下の画面構成・重なり順の入口は、この追加整理を反映している。

**推奨は、独立したアプリ内ナビゲーションを外し、「レイヤー一覧と大きなキャンバス」を主画面にすること。** 機能を一律に削るのではなく、常時見せるものを絞り、選択・編集・問題発生に応じて必要な操作を出す。StagePaneの価値は設定項目の多さではなく、見せる内容を迷わず整え、必要な瞬間に隠せることにある。

実装範囲は操作UIとその導線。観客側Stage、取得同意、フレームの消去、切り抜きの適用境界、既存の購入条件を守る。見た目の刷新と同時に新しい配信機能やシーン管理を足す計画にはしない。

## 2 Appleらしさをどう設計へ落とすか

AppleのHIGが示す内容優先、階層、標準的な操作、アクセシビリティを基準にする。ここでの具体的な配置・寸法はStagePaneに対する設計判断であり、Appleがこのレイアウトを推奨したという意味ではない。

- **内容が主役。** ニュートラルな操作面と少数の区切りで、共有する内容へ視線を集める。装飾的なグラデーション、カードの入れ子、重複見出しを除く。[Layout](https://developer.apple.com/design/human-interface-guidelines/layout)
- **頻度に合わせる。** 常用操作はツールバー、対象固有の操作は選択中の対象に対応するツール領域、低頻度のアプリ設定は標準のSettingsへ置く。[Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)、[Settings](https://developer.apple.com/design/human-interface-guidelines/settings)
- **Macの習慣を使う。** 標準メニュー、設定の `⌘,`、ウインドウ復帰、キーボード操作を整え、意味の読めるラベルを残す。[Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos)
- **透明感より判読性。** OS標準のマテリアルは操作面に限定し、映像や文字へ過剰に重ねない。透明度低減、コントラストを上げる、ダークモードを尊重する。macOS 14以降で成立する基礎を先に作る。[Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)

## 3 推奨する画面構成

```text
┌ 手元の編集画面 ──────────────────────────────────────────────┐
│ ソースを追加   配置 / 手書き   レイアウト  カーテンを閉じる  Stageを表示 │
│ 会議では「StagePane Stage」を選択                 共有ガイド      │
├ レイヤー ─────────┬ Stage出力: 内容を表示  ·  16:9 / Stage設定 ────┤
│ 資料  表示中  [目] │                                             │
│ デモ  非表示  [目] │             大きなキャンバス                 │
│ 参考  切断        │                                             │
│       [選び直す]  │                                             │
├──────────────────┼ 映像領域外: 選択対象名 / 切り抜く / …            ┤
└──────────────────┴─────────────────────────────────────────────┘
```

主画面は2列。左にレイヤー、右にキャンバスを固定し、対象を選んだときだけ局所ツールを出す。通常の配置モードでは下部ドックを常設しない。「レイアウト」メニューにグリッド、横並び、縦並び、ピクチャーインピクチャをまとめる。モードの「配置」と、構成を適用する「レイアウト」は名前と入口を分ける。

選択ツールは映像領域外の固定位置に必要時だけ領域を確保する。対象の位置へ追従して浮かせず、背面・非表示・画面端の対象でも同じ場所から操作できる。「切り抜く」は直接操作とし、重なり順は一覧のハンドルをドラッグして変更する。「ひとつ前面へ」「ひとつ背面へ」「最前面へ」「最背面へ」は、選択ツールとレイヤーの「その他」、キャンバスのコンテキストメニューにも残す。Cropではこの領域を適用／キャンセルの専用バーに置き換え、名前の長さで確定操作を押し出さない。

Stage設定はキャンバス上部の文字付きボタンから開く一つのポップオーバーとする。形・背景・ポインタ・ロゴ等を調整して閉じれば、同じ選択とキャンバスへ戻る。狭幅でも第3の常設列は作らない。長い項目はポップオーバー内で縦スクロールし、閉じる操作は固定する。出力詳細には現在のStage描画サイズをpxで表示し、「共有向けにStageを拡大」を置く。PNG寸法は書き出し内に分離し、実際の会議共有解像度は会議アプリが決めることを説明する。

**Stage設定は変更時に即反映する。閉じる操作は取消ではない。** 下書きを適用するのはCropだけである。設定内に「変更はStageへすぐ反映されます」と示し、見せる前に試す場合はカーテンを閉じる。形の変更でStageを表示する既存挙動は維持し、自動的にカーテンを開く変更は加えない。

「カーテンを閉じる／開く」は常時文字で表示する。「Stageを表示」はStageウインドウを開く／前面へ出す操作であり、会議アプリで共有を開始するボタンではない。常設の短文ガイドと状態表示も文字を失わない。初回だけ長い説明を出し、詳細は共有ガイドからいつでも読み直せる。

### 幅と余白

| 寸法 | 現行 | 推奨案の初期値 |
| --- | --- | --- |
| 対応する最小ウインドウ | 900×620pt | 維持 |
| 独立ナビ | 218pt、狭幅66pt | 撤去 |
| レイヤー | 260pt固定 | 初期232pt、220〜300ptで可変 |
| 通常行 | 選択で増段 | 56ptを基準に同じ行高。文字拡大時は全行を伸ばす |
| キャンバス左右余白 | 合計36pt | 合計32ptを起点に検証 |
| 上部常用ツール | 58pt | 約52pt、収まらなければ副操作を退避 |

900pt幅でのキャンバス領域の横幅は、現行約536〜537ptに対し約635ptが設計上の目安（900−232−区切り1−余白32）。約18%増だが、縦横比に合わせた実際の映像面積は高さにも制約されるため、面積改善の実測値ではない。1280×800pt、1440×900ptでも検証する。

レイヤー行は上段「種別＋名前」、下段「状態＋復旧操作」、末尾「表示操作／その他」の固定スロットを使う。通常状態でも下段の高さを確保し、選択で展開しない。切断時は表示操作の代わりに「選び直す」を出す。状態・復旧文字は省略せず、名前を末尾省略できる。全文はフォーカス／ホバーのヘルプとVoiceOverで読める。220ptで収まらない日英ラベルや文字サイズでは全行を同じ高さに伸ばす。長文エラーの詳細は行の「詳細」から読み、一覧内に全文を詰め込まない。

## 4 引き算と足し算

| 引くもの | 移す先・残すもの | 必要な足し算 |
| --- | --- | --- |
| Workspace内の7項目ナビ | 作業画面一本、設定・Help・Appメニューへ | 行き先の明確なメニューと戻り先 |
| 通常時の長文警告と重複注意 | 常設短文＋共有ガイド | 初回の正しいウインドウ選択案内 |
| 配置名と説明だけの下部ドック | レイアウトメニューへ | 対象選択時だけ切り抜き・重なり順 |
| 行ごとのカード枠・展開段 | 標準リスト風の行 | 状態＋名前、操作対象が動かない選択 |
| 装飾色、濃い影、操作面グラデーション | OS標準の背景・ラベル色 | 選択1色、異常はアイコンと文字を併用 |
| PNGサイズの常設表示 | 書き出しメニュー内 | Stage描画サイズとの区別 |
| 購入済みProバッジの常設 | 設定の購入状態へ | 上限到達時の説明とキャンセル復帰 |
| アイコンだけになる安全操作 | 短い文字付き操作を優先 | 狭幅でも読める状態と復旧アクション |

操作の同一メニュー内での整理を優先し、右クリック・ホバー・ショートカットだけの機能は作らない。引き算で発見可能性を失った場合は、説明を足す前に配置とラベルを見直す。

全ての操作数が減るわけではない。自動配置は当初の直接ボタン1操作から、レイアウトを開いて選ぶ2操作になる。重なり順はドラッグ操作を追加したため、前面／背面の直接ボタンは「その他」に集約する。ドラッグできない利用者にも4種類の順序変更を残す。利用者テストで頻用操作の所要時間・誤操作が悪化する場合は、一段で実行できる入口を戻す判断をする。

### 常設説明を減らす追加整理

| 減らすもの | 意味を保つ表示・入口 |
| --- | --- |
| 「ドラッグで並べ替え」の常設文 | 各行のハンドル。上ほど手前という意味はツールチップ・読み上げヒント・ヘルプに保持 |
| 空の一覧の説明 | キャンバス中央の初回追加ボタンに集約 |
| 消しゴムの手順文 | ツールアイコン、大きさの調整、ツールチップ・読み上げヒント |
| カーテン設定の自明な補足 | 見出しを「カーテンのメッセージ」へ具体化 |
| セーフエリアの常設段落 | 「セーフエリア（外周5%）」へ要点を統合し、用途はツールチップへ |
| 一般設定とProの反復説明 | 内容の短い要約、購入済み状態の1行表示、比較表に集約 |
| メニューバーの低頻度項目 | 共有案内とProは既存の設定へ、画像操作は「Stage画像」に集約 |

文字を減らす対象は手順の重複であり、状態・結果ではない。取得状態と出力状態、非表示・異常時の説明、共有先のウインドウ名、Cropの下書き、設定の即時反映、購入後の動作は維持する。

## 5 主要な操作導線

### 初回

空状態は「ソースを追加」を主操作にする。現行の3手順案内を活かし、空の補助ツールは出さない。Appleのピッカーで同意 → 新しいフレーム受信 → カーテン下で配置 → 共有ガイドでStageウインドウを確認 → 会議アプリ側で正しいStageを選び確認 → カーテンを開く。

現行では追加時にStageも開き、初期カーテンはオン。「Stageを表示」を重ねて押すことは必須にしない。ピッカーをキャンセルすれば元の空状態／構成へ戻り、会議共有が始まったとは表示しない。

### 日常の配置と切り抜き

レイヤーまたはキャンバスで選択 → 必要なら移動・等比拡大縮小 → 局所ツールで切り抜き／一覧のドラッグやその他メニューで重なり変更。背面・非表示・切断したレイヤーも一覧から選べる。選択やキャンバス上のドラッグでは重なり順を変えない。

切り抜きは対象名と「下書き」を一か所に表示し、適用／キャンセルを常に見える固定領域に置く。観客側は適用済み範囲を保持する。切り抜きは表示範囲の変更であり、取得同意の範囲を狭めるものではないことを編集内に明示する。手元では対象全体が見えるため、編集画面の共有を安全だと誤認させない。

| 切り抜き中の操作・変化 | 下書きと戻り先 |
| --- | --- |
| 別の行を単に選ぶ | 下書き対象は変えない。編集バーに対象名を保持し、重なり順・レイアウト操作はCrop完了まで無効 |
| 別レイヤーの切り抜きを明示的に開始 | 前の下書きを破棄し、その旨を通知。新対象の適用済み範囲から開始 |
| 配置／手書きへ切替 | 下書きを破棄して通知。自動適用しない |
| Stage設定、共有ガイド、Settings、Proを開閉 | 下書き・対象・フォーカス位置を保持。ウインドウを閉じるだけで適用しない |
| 対象をHide、切断、削除、置換して可視性を失う | 下書きを破棄し、適用不可と理由を通知。配置へ戻る |
| ピッカーをキャンセル | レイヤーと適用済み範囲を維持。可視性を失わなかった下書きは維持し、既に破棄した下書きは復活させない |
| カーテンを閉じる／開く | 下書きを維持。Stageへ出るのは適用済みの構成のみ |

Crop終了後は編集対象へフォーカスを戻す。対象が削除済みなら隣接する行、一覧が空なら「ソースを追加」へ戻す。

### 本番中

閉じるカーテン操作は即時実行し、確認やアニメーション完了を待たせない。カーテン中も編集内容は手元で確認できる。表示状態は「Stage出力: カーテン中／内容を表示」とし、会議アプリの実共有を検知したような「LIVE」「配信中」は使わない。

1件だけ隠す場合はレイヤーのHide。取得が一時停止し、位置・切り抜き・重なり順を保持する。再表示では新しい完全なフレームを待つ。カーテンの開閉、Hide、全停止を同じ「停止」ボタンにまとめない。

手書きのインクはStage全体に固定される。ソースの移動・Hide・切断に追従して移動／消去されるものではなく、カーテンで覆われる。明示的な全消去、全停止、削除後に公開用の出力対象が残らなくなる既存条件で消去する。非表示で保持しているセッションは残る対象に数えるため、「今見える最後の1件を削除したら必ず消える」とは言わない。インクがメモリに残ることとStageに描画されることを分け、セッションなしの待機画面ではインクを表示しない。今回、インクをソースに紐付ける新しいモデルは導入しない。

SettingsとProはWorkspaceをブロックしない独立したウインドウにする。StoreKitやAppleピッカー等のシステムUIを含め、通常の親画面操作を止めるUIがある間も既存のカーテンコマンドへの到達を実機で検証する。アプリが所有するポップオーバー／確認画面ではカーテン操作を妨げない。システムUI下でショートカットが効くと未検証のまま保証せず、確実なメニューバー経路を含めて受入条件にする。

### 切断と復旧

切断した行に「接続が切れました」と文字付き「選び直す」を表示し、対象を保持したままAppleピッカーへ戻す。古いフレームやサムネイルを観客側へ残さない。別のソースは継続する。画面全体のリセットを最初の復旧手段にしない。

### 終了

StageやWorkspaceを閉じても全取得終了とは限らない。「すべての取得を終了し、レイヤーを削除…」をStageメニューの区切られた破壊操作として残し、内容を説明する確認を維持する。停止失敗時に成功表示を出さない。WorkspaceへはDock、メニューバー、既存ショートカットから復帰できる。

## 6 状態と言葉の契約

| 表示・操作 | 意味 | 誤解させない点 |
| --- | --- | --- |
| 手元の編集画面 | 作業用ウインドウ | 会議の共有一覧から隠れる保証ではない |
| Stageを表示 | Stageの表示・前面化 | 会議共有の開始ではない |
| Stage出力: 内容を表示 | Stageが内容を描画する状態 | 視聴者への配信確認ではない |
| Stage出力: カーテン中 | 観客向け出力を覆う | 取得は継続する |
| 非表示・取得停止中 | 対象1件を隠して取得を一時停止 | レイヤー削除ではない |
| 再表示の準備中 | 再開後の新フレーム待ち | 保持フレームを先に見せない |
| 選び直す | ピッカーで対象を再承認 | 保存したウインドウへの無断再接続ではない |
| Stageウインドウを保護 | Stageの閉鎖・最小化を防ぐ | 編集ロックや配信ロックではない |
| すべての取得を終了し、レイヤーを削除 | 全取得の終了と全レイヤー・インクの消去 | 簡単な一時停止ではない |

Stage表示状態、カーテン状態、取得状態、会議共有は別の事実である。主画面はStage出力の要約と異常件数を示し、取得の内訳はレイヤーと詳細で示す。色だけの状態点にしない。

### 状態要約の優先順

ウインドウの状態を先に、内容の状態を次に決める。取得の異常件数は両者を隠さない補助表示にする。

| 条件（上から優先） | 主表示の例 |
| --- | --- |
| Stageが閉じている | 「Stageを閉じています・取得2件」または「Stageを閉じています・取得なし」 |
| Stageが最小化されている | 「Stageを最小化しています・取得2件」。復帰操作はStageを表示 |
| Stageが開き、カーテンON | 「Stage出力: カーテン中」。取得中／停止の内訳はレイヤーで確認 |
| カーテンOFF、取得セッションなし（ソースなし／全件切断など） | 「Stage出力: 待機画面」。取得先の再選択が必要なら要対応を付記 |
| カーテンOFF、セッションあり、表示可能な映像なし、取得準備中 | 「Stage出力: 映像待ち」 |
| カーテンOFF、セッションあり、表示可能な映像なし（全件Hide／出力抑制／失敗など） | 「Stage出力: 映像なし」。全件非表示等の理由を補足 |
| カーテンOFF、表示可能な映像あり | 「Stage出力: 内容を表示」 |
| 上記に取得失敗・切断が併存 | 主表示に「要対応1件」等を追加し、対象行へ移動できる |

別Spaceや他ウインドウによる遮蔽は「閉じた」と推測しない。取れる状態だけを表示する。取得件数は実際に動作しているストリーム数であり、保持レイヤー数と区別する。

「映像なし」は何も描画しない意味ではない。背景、インク（描画条件を満たす場合）、ロゴ、セーフエリアが存在し得る。待機画面・カーテン・合成映像の分岐は既存のStage描画条件と共有し、状態要約のために独自の出力判定を重複実装しない。現行の `isCaptureActive` はセッション保持を示し、Hide完了後も真になり得る。実際の取得件数を表示するにはセッションの動作状態から集計する必要がある。

### 失敗時の行と復旧

| 状態 | 文字と第一の復旧操作 |
| --- | --- |
| 初回フレーム待ち | 「映像を準備中」。旧映像なし。遅い場合の詳細にピッカー再選択を案内 |
| Hide進行中 | 「非表示にしています」。停止完了まで「取得停止中」と言わない |
| Hide失敗 | 「非表示にできませんでした・取得継続」。非表示を再試行。新フレームで表示が戻り得るためカーテンへ即到達可能にする |
| Show進行中／失敗 | 「再表示の準備中」／「再表示できませんでした」。失敗時は透明のまま、再表示を再試行 |
| 外部切断 | 「接続が切れました」。選び直す。配置・適用済みCrop・重なり順を維持 |
| ストリームの削除／全停止に失敗 | 「取得を終了できませんでした」。実取得状態と出力抑制を明示し、削除／全停止を再試行 |
| 取得停止済みで後処理だけ失敗 | 「取得は停止済み・後処理の確認が必要」。リセット可能な状態だけリセットを案内。取得継続と表示しない |
| ピッカー起動失敗／キャンセル | 失敗理由を表示／元画面へ復帰。保持レイヤーを削除せず、再試行可能 |

Hide失敗で永続的に出力抑制されるとは約束しない。基準コードの `CaptureCoordinator.swift:1451–1484` は取得継続と新しいフレーム待ちを明示している。取得エンジンを変更する案は今回のUI再設計と分けて判断する。

| 入口と結果 | 復帰の契約 |

## 8 比較した代替案

| 案 | 利点 | 弱点・判断 |
| --- | --- | --- |
| キャンバス中心（推奨） | 常設ナビを除き、対象と結果を近くする。低頻度設定を退避できる | 設定移設と標準メニューの整備が必要 |
| ナビを残す漸進案 | 「編集／Stage設定／アプリ設定」の3項目に絞る。変更範囲が小さい | 狭幅では3列と画面遷移の負担が残る。短期的な移行候補 |
| レイヤーを隠す極小案 | 初見の見た目は最も軽い | 非表示・背面・切断レイヤーの到達性を損なうため不採用 |
| 独立した本番モード | 本番中の操作数を減らせる | 新しい状態とモード切替を増やす。今回は追加しない |

「低頻度設定」という頻度は現時点の仮説である。ナビ撤去後の設定・権限説明・購入復元を見つける課題も比較する。既存利用者が新しい入口を繰り返し見失う、設定を行き来する時間が主要作業の負担になる、または独立ウインドウ化を当該リリースで検証し切れない場合は、3項目の漸進案を先行する。狭幅で得られる面積と、大画面で設定を頻用する利用者の発見可能性を別々に評価する。

会話内の画面案は合成データによる操作モックで、ナビの有無・キャンバス面積・選択／非表示／カーテン／切り抜きの関係を比較する。漸進案の設定も同じポップオーバーを使うため、設定画面を往復する負担の比較には使わない。実際の取得、新フレーム待ち、会議共有、線の描画、PNG保存、購入は再現対象外。320pxでの縦積みは会話内プレビューのためであり、実アプリの最小幅900ptを変更する提案ではない。

## 9 アクセシビリティと表示仕様

本文はシステムフォント13ptを起点、状態12pt以上を目安にする。サイズだけでなく実際の表示設定、日英の長い文字列、フォント拡大で評価する。選択色だけで状態を伝えず、VoiceOverでは名前・種別・選択状態・取得状態を合わせて通知する。

キーボード順序は常用ツール→レイヤー→キャンバス→対象ツール。Cropでは対象と適用／キャンセルに迷わず到達させ、閉じたら元の対象へフォーカスを戻す。既存のカーテン `⇧⌘H`、Workspace復帰 `⌘1` 等のコマンドを保持し、OSやテキスト編集との衝突を確認する。

一覧にフォーカスがあるときの上下キーは行選択に使い、ソースを動かさない。キャンバスの編集対象にフォーカスを移してから矢印で位置移動、Shiftで大きく移動、Optionで等比サイズ変更とする。現行の行上の矢印が移動を行う挙動からの意図的変更であり、操作ヒントと移行テストが必要。VoiceOverには位置・サイズ・重なり順の名前付き操作を用意し、標準メニューからも実行できるようにする。

行はソースIDで同一性を保つ。Hide／Showや再選択でボタンの文言・種類が変わっても同じ行にフォーカスを保ち、操作ボタンが消えたら行本体へ戻す。復旧結果は「資料を再表示しました」のように対象名と結果を一度通知する。異常が発生しただけではフォーカスを奪わない。選択ツールのアクセシビリティ名にも対象を含める。

一覧の削減で操作対象の高さやクリック領域を削りすぎない。マウス用は少なくとも28×28ptを初期目安として隣接誤操作を検証し、重要なカーテンは文字付き標準ボタンとする。選択枠は映像の実際の表示範囲に一致させる。透明度低減時は不透明面、動きを減らす設定では必要な状態変化を短く明確に示す。

## 10 実装順と合流点

1. **情報設計を減らす。** 独立ナビの撤去、Settings・標準メニューへの移設、配置の入口統合、PNG寸法とPro表示の退避。既存コマンドを呼び、取得処理は変えない。
2. **状態と対象操作を整える。** 文字付きカーテン、共有ガイド、固定高レイヤー、選択ツール、切断行の直接復旧、Cropの単一編集バー。状態遷移は既存モデルを参照する。取得件数の実状態集計とProの継続コンテキストは、UI移設に必要な状態管理の変更として明示して実装する。
3. **視覚を整える。** システムカラー、ライト対応、余白、行密度、フォーカス、素材表現。実操作とアクセシビリティを検証して寸法を確定する。
4. **公開説明を揃える。** Help、README、製品仕様、合成スクリーンショット、App Review向け説明を最終挙動に合わせる。

主な実装対象は `StageWorkspaceView.swift`、`StageLayoutEditor.swift`、`SettingsPanels.swift`、`ControlRoomView.swift`、`StagePaneApp.swift`、`StatusItemController.swift`。共通の操作モデルを使い、メニューとボタンで異なる状態遷移を複製しない。

並行開発の虫眼鏡が合流する場合は、観客へ出る拡大か手元だけの拡大かを先に確定する。独立した常設ドックを増やさず、選択したツールの設定だけを出す。同時に表示できない手書き・切り抜き・ポインタとの排他、カーテン、PNGへの反映を再レビューする。今回の基準コミットには含まれないため、この提案で受入済みとは扱わない。
